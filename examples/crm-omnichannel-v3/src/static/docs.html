Introdução

CRM Enterprise Omnichannel

Documentação estruturada completa do projeto construído sobre o padrão AIDD v3.0 com Vertical Slice Full-Stack, Dual-Database e Webhooks em tempo real.

Porta de Operação

Servidor local ativo na porta 3001.

Motor de Dados

SQLite WAL mode para desenvolvimento local e suporte a PostgreSQL em produção.

Design System

Interface Impeccable (Zero emojis, ícones vetoriais SVG, tema escuro glassmorphism).

Arquitetura de Software

Arquitetura Vertical Slice & Clean Kernel

Diferente de arquiteturas em camadas tradicionais que espalham a lógica de uma funcionalidade em dezenas de pastas, o AIDD v3.0 adota **Vertical Slices (Fatias Verticais)**. Cada módulo encapsula seu modelo de dados, serviços de negócio, rotas REST, componentes de frontend e testes de forma 100% autônoma.

Estrutura de Diretórios da Aplicação
src/
├── core/               # Kernel: Database (Dual DB), EventBus, OpenAPI 3.0, Webhooks
├── shared/             # Kernel Compartilhado: Formatters, Crypto, Validators, SVG Icons
├── modules/            # Fatias Verticais Desacopladas
│   └── [modulo]/
│       ├── backend/    # Models (SQLite/Postgres), Services, Routes REST
│       └── frontend/   # Markup e Componentes Impeccable
└── static/             # SPA de Produção com Glassmorphism
Governança & Tokens

Engenharia Agêntica & Economia Extrema de Tokens

O desenvolvimento deste projeto seguiu com rigor as **3 Regras de Ouro da Engenharia Agêntica**, garantindo zero poluição do chat principal e economia semanal superior a 99%:

Regra de Ouro Mecanismo Técnico Impacto no Consumo
1. Não usar o chat como terminal Compilação, testes unitários (pytest) e gates executam no motor mecânico Python local. 99.3% de economia de tokens
2. Worktrees do ORCA Cada módulo ou projeto construído em ambiente isolado e sem contaminação. Zero vazamento de contexto
3. Plano JSON Estruturado Retomada de sessão imediata via PLANO-EXECUCAO-ESTRUTURADO.json. Retomada em 500 tokens

Automação

Integração com Webhooks & n8n / Zapier

Toda mutação de dados relevante emite um evento no EventBus, que é despachado assincronamente pelo WebhookDispatcher via HTTP POST em background (sem travar a resposta do usuário):

Exemplo de Payload de Webhook Disparado 
{
  "evento": "lead.criado",
  "timestamp": 1788224000,
  "origem": "CRM Enterprise Omnichannel",
  "dados": {
    "id": 1,
    "status": "sucesso",
    "detalhes": "Operação processada com validação criptográfica"
  }
}
